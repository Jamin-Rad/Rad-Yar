# Kartino / RadYar bridge (iOS 1.4)

Optional connection starts only in Settings, with separate RadYar browser login and consent. S256 PKCE and state protect a one-use ten-minute authorization code. A 180-day opaque link token stays in Keychain; only its hash is stored on the server. Both an active Kartino session and link token are required. Immutable Clerk user IDs own progress, with legacy progress accessed only through the website's existing verified ownership claims.

The managed RadYar tree follows the website curriculum and uses bundled topic artwork. Personal libraries remain separate. A complete ID/hash manifest carries only changed deck contents; progress is sent when changed or after a review batch. Cards are localized to fa/de/en (English fallback). Existing website access rules apply: free users have two topics and five-card sessions. Offline permission renews at least weekly and respects earlier subscription/trial expiry.

Ratings and outgoing events commit atomically to the local account library. Events carry a UUID, card ID, previous review timestamp, outcome and local schedule, in batches of at most 500. The server serializes mobile writes, deduplicates events and checks the causal base. A conflicting review is acknowledged without overwriting newer server progress; the app displays a conflict notice. Removed source-card events are acknowledged as conflicts. A database trigger protects against stale web snapshots. Reviews made during a network request remain in the local queue and are not overwritten by its response.

Sync runs manually, on entering RadYar when stale by 15 minutes, and when leaving study with pending reviews. No polling or continuous background worker. Failure preserves the queue. Disconnect first flushes pending results, then revokes the link and removes the managed local copy; website data and personal cards remain. Account deletion cascades link/event records. Personal backups exclude managed cards, credentials and queues; restoring a personal backup preserves the currently linked library. Source content is read-only; study offers a personal editable copy.

Validation: catalog/entitlement/wire-contract tests; Swift offline queue/persistence/concurrent-response/backup/account-isolation checks; existing 72 model/import/schedule checks and persistence suite. Rolled-back SQL fixture verifies PKCE mismatch, code replay, event retries, stale-base conflicts, valid causal reviews, stale web snapshots and deletion cascade. Tables are service-only with RLS, public role grants revoked, and SECURITY INVOKER functions with explicit search paths.
